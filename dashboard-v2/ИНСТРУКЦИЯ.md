# 📋 Инструкция по публикации дашборда онлайн

## Структура проекта

```
dashboard-v2/
├── public/
│   ├── index.html           ← главный файл дашборда
│   └── supabase-client.js   ← клиент базы данных
├── netlify/
│   └── functions/
│       └── bitrix.js        ← прокси для Bitrix24 (webhook скрыт)
├── netlify.toml             ← конфиг деплоя
└── supabase-schema.sql      ← SQL таблицы для базы
```

---

## ШАГ 1 — Supabase (база данных + авторизация)

### 1.1 Создайте проект
1. Зайдите на [supabase.com](https://supabase.com)
2. **New project** → придумайте название и пароль базы
3. Дождитесь создания (~2 мин)

### 1.2 Создайте таблицы
1. **SQL Editor** → **New query**
2. Вставьте содержимое файла `supabase-schema.sql`
3. Нажмите **Run** (F5)

### 1.3 Скопируйте ключи
**Settings → API:**
- **Project URL** → `https://xxxx.supabase.co`
- **anon public** key → длинная строка

### 1.4 Вставьте ключи в дашборд
Откройте `public/index.html`, найдите блок:
```javascript
window.APP_CONFIG = {
  SUPABASE_URL: 'https://YOUR_PROJECT.supabase.co',
  SUPABASE_ANON_KEY: 'YOUR_ANON_KEY',
};
```
Замените значения на ваши из п.1.3.

### 1.5 Создайте пользователей
1. **Authentication → Users → Add user**
2. Введите email и пароль для каждого

### 1.6 Назначьте роль admin
В **SQL Editor** выполните:
```sql
UPDATE profiles SET role = 'admin' WHERE email = 'ваш@email.ru';
```
Остальные пользователи будут viewer (только просмотр).

## ШАГ 2 — Netlify (хостинг)

### Быстрый способ (без Netlify CLI):
1. Зайдите на [netlify.com](https://netlify.com) → зарегистрируйтесь
2. **Add new site → Deploy manually**
3. Перетащите папку **`public`** в окно загрузки
4. Готово — получите ссылку вида `https://xxx.netlify.app`

> ⚠️ При этом способе Netlify Functions (прокси Bitrix24) **не работают**.
> Для их работы нужен деплой через Git или CLI (см. ниже).

### Полный способ (с Functions для Bitrix24):

**Через GitHub:**
1. Создайте репозиторий на [github.com](https://github.com)
2. Загрузите папку `dashboard-v2` целиком
3. В Netlify: **Import from Git** → выберите репозиторий
4. Build settings: оставьте пустыми (netlify.toml всё настроит)
5. **Deploy**

**Через Netlify CLI:**
```bash
npm install -g netlify-cli
cd dashboard-v2
netlify login
netlify deploy --prod
```

## ШАГ 3 — Переменные окружения Netlify

**Site settings → Environment variables → Add a variable:**

| Key | Value |
|-----|-------|
| `BITRIX_WEBHOOK_URL` | `https://convertix.bitrix24.ru/rest/1/ВАШ_ТОКЕН/` |

> 🔒 После добавления: **Deploys → Trigger deploy → Deploy site**

> Webhook Bitrix24 **не будет виден** в коде страницы — он хранится только на сервере Netlify.

## Быстрый старт (без Supabase)

Если нужно быстро опубликовать **для одного пользователя**:
1. Загрузите папку `public` на Netlify (Deploy manually)
2. Зайдите: Email — пустой, Пароль — `leads2024`
3. Данные будут в localStorage браузера (не синхронизируются)

## Безопасность

| Данные | Где хранятся | Видны в коде? |
|--------|-------------|--------------|
| Webhook Bitrix24 | Netlify env vars | ❌ Нет |
| Supabase URL | index.html | ✅ Да (норм.) |
| Supabase anon key | index.html | ✅ Да (норм.) |
| Пароли пользователей | Supabase Auth | ❌ Нет |
| Ставки, брак, расходы | Supabase DB | ❌ Нет (RLS) |
| Фильтры | localStorage | — только у юзера |

> **Примечание:** Supabase anon key можно хранить во frontend — это нормально.
> Он позволяет только читать/писать данные с учётом RLS-политик (авторизация обязательна).

## Смена пароля (локальный режим)

Откройте `index.html`, найдите:
```javascript
if(password === atob('bGVhZHMyMDI0'))
```
Замените `bGVhZHMyMDI0` на base64 нового пароля.
Получить base64: в консоли браузера выполните `btoa('новый_пароль')`.
